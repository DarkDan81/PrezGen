# Stage 11 Decisions

## 1. Источник данных демо

Решение:

1. Используем отдельные идентификаторы сущностей:
- тема: `demo-festive-ru`,
- презентация: `demo-guided-ru`.
2. При повторном запуске сценарий обновляет существующие сущности, а не плодит копии.

Причина:
- повторяемость для демо/тестов,
- чистота окружения.

## 2. Формат guided-тура

Решение:

1. Запуск тура кнопкой в главном меню (`Запустить демо`), доступной любому пользователю.
2. Встроенный фронтовый тур (оверлей + подсветка + шаги) вместо внешнего Playwright.
3. Шаги хранятся в конфиге (TS/JSON), чтобы легко править порядок и тексты.
4. Режим автопилота: шаг с пояснением показывается дольше (в среднем 6-8 секунд), затем подсказка скрывается и действие выполняется автоматически.
5. Подсказка фиксируется по центру экрана, чтобы не «прыгала» по интерфейсу.

Причина:
- стабильнее в рантайме,
- подходит и для onboarding, и для пресейл-демо.

## 3. Структура демо-сюжета

Решение:

1. Сначала "редактор тем": показываем ключевые токены и автоприменение.
2. Затем "редактор презентации": автосборка слайдов и блоков.
3. Затем "быстрая смена тем" на слайде с 4 блоками.
4. Финал: подсветка трех кнопок экспорта.

Причина:
- от общего к частному,
- быстрый wow-эффект без перегруза.

## 4. Тексты слайдов

Решение:

1. Переводим тестовую презу на русский.
2. Каждый слайд получает объясняющий контекст:
- что именно демонстрирует,
- какой функционал валидирует.

Причина:
- тестеру понятно "зачем это",
- меньше ложных замечаний.

## 5. Безопасность сценария

Решение:

1. Все действия выполняются только над демо-сущностями по фиксированным ID.
2. Демо-сущности перезаписываются при каждом запуске, чтобы интерактив всегда был в согласованном состоянии.
3. Экспортные кнопки в guided-режиме только подсвечиваются и объясняются; авто-скачивание не выполняется.

Причина:
- исключить случайное повреждение рабочих презентаций пользователя.
